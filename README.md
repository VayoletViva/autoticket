# autoticket

Утилита на Rust: следит за новыми тикетами в техподдержке, сразу берёт каждый новый тикет и присылает в Telegram-бот сообщение с его данными (номер, тема, поля, время захвата).
Работает в фоне, сама запускается при старте системы, переживает обрывы сети и истёкший вход.

📘 Подробная пошаговая инструкция с нуля: [docs/INSTALL.md](docs/INSTALL.md)

## Почему сайт, а не мини-приложение Telegram

Программа работает с **JSON API сайта техподдержки**, то есть с теми же запросами, которые шлёт страница сайта в браузере.
- Мини-приложение входит через Telegram `initData`. Эти данные подписывает и выдаёт только клиент Telegram в момент открытия приложения, и срок их действия ограничен. Без человека их можно получить только через userbot на вашем аккаунте, а это ненадёжно и грозит ограничениями аккаунта.
- На сайте обычный вход по логину и паролю. Программа может повторять его сама, когда сессия истекает (ответ 401).
- Обычно у сайта и мини-приложения один бэкенд, поэтому по скорости разницы нет.
- Автоматизацию браузера (Selenium/headless) я не использовал: это сотни миллисекунд на действие и много памяти.

## Сборка

```bash
curl https://sh.rustup.rs -sSf | sh       # Windows: https://rustup.rs
cargo build --release                       # бинарник: target/release/autoticket (.exe)
cargo install --path .                      # по желанию: в ~/.cargo/bin, удобно для автозапуска
```
Проверки: `cargo test` и `cargo clippy --all-targets -- -D warnings`.

## Как найти эндпоинты вашего сайта

Настоящий API вашей техподдержки программе неизвестен, поэтому всё настраивается в `config.toml`.
1. Откройте сайт, нажмите F12 → **Network** → фильтр **Fetch/XHR**.
2. Войдите. Найдите запрос входа (обычно POST `.../login`) и запишите путь, имена полей логина и пароля, а также где в ответе лежит токен (например `{"token": "..."}` → `/token`). Если токена нет и сервер ставит cookie, укажите `token_pointer = ""`.
3. Откройте список новых тикетов и найдите запрос, который его загружает. Запишите путь и где в ответе массив (`[...]` → `""`, `{"data":{"items":[...]}}` → `/data/items`), id и тема (`/id`, `/subject`).
4. Нажмите «Взять» на любом тикете и запишите метод, путь (номер замените на `{id}`) и тело, если оно есть.

Пути вида `/data/items` записываются в формате JSON Pointer: через `/` от корня ответа. Все поля описаны в `config.example.toml`.

**Капча, 2FA или SSO?** Выберите в настройке способ входа «2 — токен». Скопируйте из DevTools значение заголовка `Authorization` (без `Bearer`) или `Cookie` любого запроса.
Когда токен истечёт, бот пришлёт предупреждение. Запустите `autoticket setup` и вставьте новый токен: работающая программа подхватит его сама.

**Вход через Telegram («Войти через Telegram»)?** Сам вход через Telegram программа не проходит: Telegram каждый раз просит подтверждения в приложении. Но это и не нужно. После входа сайт выдаёт обычную сессию (cookie), и программа использует её:
войдите на сайт в отдельном профиле браузера, скопируйте из DevTools строку `Cookie` запроса списка тикетов, выберите в `autoticket setup` способ «2» и имя заголовка `Cookie`, затем закройте окно, не нажимая «Выйти».
Если сервер обновляет cookie (`Set-Cookie`), программа принимает новое значение и хранит его в `session.json` рядом с конфигом, поэтому сессия переживает перезагрузку. Для коротких Bearer-токенов есть `refresh_path`.
Пошагово и с подводными камнями: [docs/INSTALL.md, раздел 6.6](docs/INSTALL.md#66-сайт-со-входом-через-telegram-войти-через-telegram).

## Telegram

1. В @BotFather выполните `/newbot` и скопируйте токен.
2. Напишите своему боту `/start`. Во время настройки chat_id определится автоматически.

## Первый запуск

```bash
./autoticket setup        # вопросы: сайт, вход, бот; проверка онлайн и тестовое сообщение
./autoticket run          # проверить вручную (Ctrl+C — остановить)
./autoticket test-notify  # ещё одно тестовое сообщение
```
`autoticket run` без конфигурации задаёт те же вопросы. Дальше программа ничего не спрашивает.

Данные сохраняются в `config.toml` в папке пользователя. Посмотреть путь: `autoticket paths`.
- Linux: `~/.config/autoticket/config.toml`
- Windows: `%APPDATA%\autoticket\config\config.toml`
- macOS: `~/Library/Application Support/autoticket/config.toml`

Файл не лежит в репозитории (и есть в `.gitignore`). На Linux и macOS у него права `0600`. Другую папку можно задать через `--config-dir DIR` или `AUTOTICKET_CONFIG_DIR`.

## Автозапуск

```bash
autoticket install-autostart     # отключить: autoticket uninstall-autostart
```
- **Linux:** создаётся systemd user-сервис `~/.config/systemd/user/autoticket.service` (Restart=always), затем выполняются `systemctl --user enable --now autoticket` и `loginctl enable-linger $USER`. Благодаря linger сервис стартует после перезагрузки даже без входа в систему.
  Проверка: `systemctl --user status autoticket`, логи — `journalctl --user -u autoticket -f`. После `setup` выполните `systemctl --user restart autoticket`.
- **Windows:** создаётся задание «autoticket» в Планировщике заданий: запуск при входе пользователя, без окна, без лимита времени, перезапуск при сбое. Проверка: Планировщик заданий → autoticket.
  Чтобы задание стартовало до входа в систему: свойства задания → «Выполнять для всех пользователей» и триггер «При запуске».
- **macOS:** создаётся `~/Library/LaunchAgents/com.autoticket.plist` (RunAtLoad, KeepAlive) и загружается через `launchctl load -w`.

Перед установкой автозапуска положите бинарник в постоянное место (например, через `cargo install --path .`): в сервис записывается полный путь к нему.
Чтобы проверить автозапуск, перезагрузите машину и посмотрите статус или лог: должна появиться строка «autoticket запущен».

## Логи и замеры

- Логи пишутся в `<папка данных>/logs/autoticket.YYYY-MM-DD.log` (ротация раз в день, хранится 14 файлов) и в stdout. Уровень задаёт `RUST_LOG=debug`.
- Каждый захват записывается в `claims.csv`: `timestamp_utc, ticket_id, claim_rtt_ms, detect_to_claim_ms, outcome`.
- `autoticket bench` замеряет задержку до вашего сервера и ничего не берёт. Отчёт с замерами: [docs/REPORT.md](docs/REPORT.md).

## Ошибки и нагрузка на сервер

- Ошибки сети, 5xx и таймауты пишутся в лог, следующая попытка идёт с растущей паузой (до `max_backoff_ms`). Если связи нет больше 5 минут, бот присылает предупреждение.
- На 401/403 программа один раз входит заново. Если вход отклонён, бот присылает предупреждение, а следующая попытка будет только через `max_backoff_ms`, чтобы аккаунт не заблокировали.
- Ответ 429 соблюдается вместе с `Retry-After`. Если бот недоступен, сообщения ждут в очереди с повторами, а захват при этом не тормозится.
- Список опрашивается раз в `poll_interval_ms` (по умолчанию 1000 мс, минимум 250). Ставить меньше 250–500 мс не стоит: тикет будет обнаружен на доли секунды раньше, а нагрузка на сервер вырастет кратно.
  Захват отправляется сразу после обнаружения, все новые тикеты берутся параллельно. Тикет, который не удалось взять, пробуется не больше 3 раз.

## Удаление

`autoticket uninstall-autostart`, затем удалите бинарник и папку конфигурации (`autoticket paths`; там же `session.json` с сессией сайта).
