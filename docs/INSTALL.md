# autoticket: установка и запуск с нуля

Этот гайд ведёт от компьютера, на котором нет ни Git, ни Rust, до программы, которая сама стартует при включении, берёт новые тикеты и присылает о каждом сообщение в Telegram. Команды даны для **Windows (PowerShell)** и для **Linux-сервера (Ubuntu/Debian, bash)**, macOS описана кратко.

Все команды, вопросы мастера настройки и сообщения в логах взяты из кода программы и из пробного прогона в чистом Linux. Вывод в примерах настоящий, только секреты заменены на выдуманные.

## 0. Что это и что понадобится

`autoticket` — это одна программа (один исполняемый файл). Она раз в секунду (интервал настраивается) спрашивает у сайта техподдержки список новых тикетов. Новый тикет она сразу берёт тем же запросом, который отправляет кнопка «Взять» на сайте, и присылает вам в Telegram его номер, тему и время захвата. Она работает в фоне, переживает обрывы сети и истёкший вход, а при долгих проблемах предупреждает вас через бота.

Программа работает с **сайтом** техподдержки, а не с мини-приложением в Telegram. Вход в мини-приложение выдаёт только клиент Telegram, и этот вход быстро истекает, а на сайте программа может сама входить заново по логину и паролю. Подробнее — в [README](../README.md#почему-сайт-а-не-мини-приложение-telegram).

### Требования

| Что | Подробности |
|---|---|
| Операционная система | Windows 10/11 (64-бит), Linux с systemd (Ubuntu 20.04+, Debian 11+ и т. п.), macOS 12+ |
| Диск | около 2 ГБ свободного места на время сборки (папка `target`), готовая программа весит около 10 МБ |
| Память | от 1 ГБ RAM для сборки; на маленьком сервере (512 МБ) нужен swap, см. [Проблемы](#сборка-падает-killed-signal-9-не-хватает-памяти). Работающей программе хватает около 10–20 МБ |
| Интернет | нужен для скачивания Rust и библиотек, а потом для доступа к сайту техподдержки и `api.telegram.org` |
| Git | по желанию: можно скачать ZIP-архив вместо `git clone` |
| Rust | стабильная версия **1.88 или новее** (в проекте `edition = "2024"`). Ставится через `rustup` |
| Компилятор C | нужен библиотеке шифрования `ring`. Windows: **Visual Studio Build Tools** с нагрузкой «Разработка классических приложений на C++» (установщик Rust предложит их сам). Linux: пакет `build-essential`. macOS: Xcode Command Line Tools |
| Аккаунты | ваш логин на сайте техподдержки и аккаунт Telegram |

**Python, `requirements.txt` и OpenSSL не нужны.** Это программа на Rust. Её библиотеки перечислены в [`Cargo.toml`](../Cargo.toml), и `cargo` скачивает их сам при первой сборке:

| Библиотека | Зачем |
|---|---|
| `tokio` | асинхронная работа: опрос, захват и уведомления идут параллельно |
| `reqwest` (+ `rustls`, `ring`) | HTTPS-запросы к сайту и к Telegram, шифрование без OpenSSL |
| `serde`, `serde_json`, `toml` | разбор JSON-ответов сайта и файла настроек `config.toml` |
| `clap` | команды `setup`, `run`, `bench` и т. д. |
| `rpassword` | ввод пароля без отображения на экране |
| `directories` | системные папки для настроек и логов |
| `tracing`, `tracing-subscriber`, `tracing-appender` | логи в консоль и в файлы с ежедневной ротацией |
| `anyhow`, `thiserror`, `url`, `humantime` | ошибки, адреса, формат времени |
| `wiremock`, `tempfile` | только для тестов: имитация сайта и Telegram |

## 1. Скачивание

### Вариант А: через Git (рекомендуется, так проще обновлять)

Если Git не установлен:
- **Windows:** скачайте установщик с https://git-scm.com/download/win и установите со всеми настройками по умолчанию. Или в PowerShell: `winget install --id Git.Git -e`.
- **Linux:** `sudo apt update && sudo apt install -y git`
- **macOS:** `xcode-select --install` (вместе с компилятором поставит и Git).

Скачайте репозиторий в домашнюю папку:

```powershell
# Windows (PowerShell)
cd $HOME
git clone https://github.com/VayoletViva/autoticket.git
cd autoticket
```

```bash
# Linux / macOS
cd ~
git clone https://github.com/VayoletViva/autoticket.git
cd autoticket
```

### Вариант Б: ZIP-архив, без Git

1. Откройте https://github.com/VayoletViva/autoticket.
2. Нажмите зелёную кнопку **Code → Download ZIP**.
3. Распакуйте архив, например в `C:\Users\<вы>\autoticket`. Внутри может оказаться ещё одна папка `autoticket-main`, работать нужно в ней.
4. Откройте эту папку в терминале. На Windows: в Проводнике зажмите Shift, щёлкните правой кнопкой мыши по пустому месту в папке и выберите **«Открыть окно PowerShell здесь»** (или «Открыть в Терминале»).

### Проверка: вы в правильной папке

```powershell
ls        # Windows и Linux одинаково
```

Должны быть видны: `Cargo.toml`, `Cargo.lock`, `config.example.toml`, `README.md`, папки `src`, `tests`, `docs`. Если их нет, вы на уровень выше или ниже нужной папки.

## 2. Установка Rust и компилятора C

### Windows

1. Скачайте **rustup-init.exe** с https://rustup.rs (кнопка «rustup-init.exe (64-bit)») и запустите.
2. Если Visual Studio Build Tools не установлены, установщик напишет об этом и предложит поставить их: согласитесь (вариант **1**). Откроется Visual Studio Installer. Там должна быть отмечена нагрузка **«Разработка классических приложений на C++»** («Desktop development with C++»): дождитесь окончания установки (несколько гигабайт).
   Если установщик этого не предложил, поставьте Build Tools вручную: https://visualstudio.microsoft.com/visual-cpp-build-tools/ → та же нагрузка.
3. Вернитесь в окно rustup-init и на вопрос о типе установки выберите **1) Proceed with standard installation (default)**.
4. **Закройте и заново откройте PowerShell**, иначе команда `cargo` не найдётся.

### Linux (Ubuntu/Debian)

```bash
sudo apt update
sudo apt install -y build-essential curl git
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source ~/.cargo/env
```

`source ~/.cargo/env` нужен только в текущем окне: в новых терминалах путь подхватится сам.

### macOS

```bash
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source ~/.cargo/env
```

### Проверка

```bash
rustc --version
cargo --version
```

Пример (в проверочном прогоне):

```
rustc 1.100.0 (0ef1bc386 2026-11-09)
cargo 1.100.0 (3acc79c0c 2026-11-05)
```

Номер версии должен быть **1.88 или больше**. Если Rust у вас стоял раньше и версия старше, обновите: `rustup update stable`.

## 3. Сборка

В папке проекта (там, где лежит `Cargo.toml`):

```bash
cargo build --release
```

Первая сборка скачивает библиотеки и компилирует их: 3–10 минут на обычном компьютере, дольше на слабом сервере. В конце должна появиться строка вида:

```
    Finished `release` profile [optimized] target(s) in 4m 12s
```

Готовая программа:
- Windows: `target\release\autoticket.exe`
- Linux/macOS: `target/release/autoticket`

Проверьте, что она запускается:

```powershell
# Windows
.\target\release\autoticket.exe --help
```

```bash
# Linux / macOS
./target/release/autoticket --help
```

Настоящий вывод:

```
Автоматически берёт новые тикеты техподдержки и присылает уведомления в Telegram

Usage: autoticket [OPTIONS] [COMMAND]

Commands:
  run                  Работать: следить за новыми тикетами и брать их (по умолчанию)
  setup                Ввести или изменить данные для входа и Telegram
  test-notify          Отправить тестовое сообщение в Telegram
  bench                Замерить задержку запросов по тёплому соединению (тикеты не берутся)
  install-autostart    Включить автозапуск при старте системы
  uninstall-autostart  Отключить автозапуск
  paths                Показать, где лежат конфиг, логи и claims.csv
  help                 Print this message or the help of the given subcommand(s)

Options:
      --config-dir <DIR>  Папка с config.toml, логами и claims.csv (по умолчанию системная папка пользователя или $AUTOTICKET_CONFIG_DIR)

Без подкоманды выполняется `run`. Первый запуск: `autoticket setup`.
```

По желанию (для разработчиков) можно запустить тесты: `cargo test`. Они проверяют захват тикета и отправку уведомления на имитации сайта и Telegram, повторный вход, первый запуск и т. д. Реальный сайт и реальный бот тесты не трогают.

## 4. Установка программы в постоянное место

Автозапуск запоминает **полный путь** к программе. Если запускать её из `target\release`, то после `cargo clean`, переноса или удаления папки с исходниками автозапуск сломается. Поэтому установите программу в стандартную папку Rust:

```bash
cargo install --path .
```

Программа скопируется в:
- Windows: `%USERPROFILE%\.cargo\bin\autoticket.exe` (то есть `C:\Users\<вы>\.cargo\bin\autoticket.exe`)
- Linux/macOS: `~/.cargo/bin/autoticket`

Эта папка уже добавлена в PATH установщиком Rust, поэтому дальше команда пишется просто как `autoticket ...` из любой папки. Проверка:

```bash
autoticket --version
```

Если `cargo install` вы делать не хотите, во всех командах ниже пишите полный путь (`.\target\release\autoticket.exe` или `./target/release/autoticket`) и не удаляйте эту папку.

## 5. Создание Telegram-бота

1. Откройте в Telegram **@BotFather** (с синей галочкой) и нажмите **Start**.
2. Отправьте `/newbot`.
3. Введите отображаемое имя, например `Мои тикеты`.
4. Введите username бота: латиницей, обязательно с окончанием `bot`, например `ivan_tickets_bot`.
5. BotFather пришлёт **токен** вида `123456789:AAH...` (цифры, двоеточие, буквы). Скопируйте его: он понадобится в шаге 7.
6. Откройте своего нового бота (ссылка `t.me/ivan_tickets_bot` в том же сообщении) и нажмите **Start**. Без этого бот не сможет вам писать.

> ⚠️ Токен бота — это пароль. Не пересылайте его и не выкладывайте в GitHub. Если он утёк, в @BotFather выполните `/revoke` и потом `autoticket setup`, чтобы вставить новый.

`chat_id` (номер чата, куда писать) искать не нужно: мастер настройки определит его сам, когда вы отправите боту `/start`.

## 6. Настройка: как найти API своего сайта техподдержки

Программе нужно знать три запроса вашего сайта: **вход**, **список новых тикетов** и **«Взять тикет»**. У каждого сайта они свои, поэтому их нужно один раз подсмотреть в браузере. Это займёт 10–15 минут. Если всё совпадёт со значениями по умолчанию, этот шаг можно пропустить, но так бывает редко.

### 6.1. Открываем инструменты разработчика

1. Откройте сайт техподдержки в **Chrome** или **Edge** (в Firefox всё так же, названия чуть другие). Если вы уже вошли, выйдите из аккаунта.
2. Нажмите **F12** (или Ctrl+Shift+I). Откройте вкладку **Network** («Сеть»).
3. Включите фильтр **Fetch/XHR**: так видны только запросы к API, без картинок и стилей.
4. Поставьте галочку **Preserve log** («Сохранять журнал»), чтобы запросы не пропадали при переходе между страницами.

Щёлкнув по запросу в списке, справа вы увидите вкладки:
- **Headers**: `Request URL` (адрес) и `Request Method` (GET/POST/…), ниже **Request Headers** (заголовки, в том числе `Authorization` и `Cookie`);
- **Payload**: что отправил браузер (тело запроса);
- **Response** (или **Preview**): что ответил сервер.

### 6.2. Запрос входа

Войдите на сайт. В списке появится запрос с именем вроде `login`, `auth`, `signin`, `session`, обычно метода **POST**. Запишите:

| Что смотреть | Где | Параметр в config.toml |
|---|---|---|
| Адрес сайта без пути, например `https://support.example.com` | Headers → Request URL, часть до третьего `/` | `base_url` |
| Путь, например `/api/auth/login` | Headers → Request URL, остаток | `login_path` |
| Имена полей логина и пароля, например `{"email": "...", "password": "..."}` → `email` и `password` | Payload | `login_username_field`, `login_password_field` |
| Где в ответе токен, например `{"access_token": "eyJ..."}` → `/access_token` | Response | `token_pointer` |

**Как понять, токен или cookie.** Если в ответе входа есть длинная строка (`token`, `access_token`, `jwt`…), а следующие запросы содержат заголовок `Authorization: Bearer <та же строка>`, то это токен: укажите путь к нему в `token_pointer`. Если в ответе токена нет, а в Response Headers входа есть `Set-Cookie`, то сайт держит сессию в cookie: поставьте `token_pointer = ""`, программа сама сохранит и будет отправлять cookie.

> Если вход отправляется не как JSON, а как обычная форма (в Payload написано `Form Data`), автоматический вход не подойдёт. Используйте режим «токен» (раздел 6.5).

### 6.3. Запрос списка новых тикетов

Откройте страницу с новыми (неназначенными) тикетами и найдите запрос, который загружает список: в Response будут тикеты. Запишите:
- метод и путь (обычно **GET**, например `/api/tickets?status=new`) → `list_method`, `list_path`;
- если список берётся POST-запросом с телом, скопируйте тело из Payload → `list_body`;
- где в ответе массив тикетов, номер тикета и тема.

Пути внутри ответа записываются в формате **JSON Pointer**: от корня ответа через `/`. Разберём выдуманный пример ответа:

```json
{"data": {"items": [
  {"id": 42, "subject": "Не работает принтер", "status": "new", "priority": "high", "created_at": "2026-11-26T09:15:00Z"}
]}}
```

| Что | JSON Pointer | Параметр |
|---|---|---|
| массив тикетов | `/data/items` (если ответ сам является массивом `[...]`, то пусто: `""`) | `list_items_pointer` |
| номер тикета внутри элемента | `/id` | `id_pointer` |
| тема | `/subject` | `title_pointer` |
| поля для сообщения в Telegram | `/priority`, `/created_at` | `extra_fields` |
| брать только тикеты со статусом `new` | `/status` и значение `new` | `filter_pointer`, `filter_values` |

Те же строки в `config.toml`:

```toml
list_path = "/api/tickets?status=new"
list_items_pointer = "/data/items"
id_pointer = "/id"
title_pointer = "/subject"
extra_fields = ["/priority", "/created_at"]
filter_pointer = "/status"
filter_values = ["new"]
```

Вложенные поля пишутся через `/`: `{"author": {"name": "Пётр"}}` → `/author/name`. Элемент массива указывается номером с нуля: `/tags/0`.

### 6.4. Запрос «Взять тикет»

Нажмите на сайте «Взять» («Назначить на себя», «Assign to me») на любом тикете. Если тикеты брать сейчас нельзя, сделайте это при первой возможности. Появится запрос, например `POST /api/tickets/42/assign`. Запишите:
- метод → `claim_method` (`POST`, `PUT`, `PATCH`…);
- путь, **заменив номер тикета на `{id}`**: `/api/tickets/{id}/assign` → `claim_path`;
- тело из Payload, если оно есть, например `{"assignee": "agent@example.com"}`. Его можно записать шаблоном: `claim_body = '{"assignee": "{username}"}'`. Программа подставит `{id}` (номер тикета) и `{username}` (ваш логин).

Ссылку на тикет для сообщения в Telegram можно задать шаблоном: `ticket_url = "https://support.example.com/tickets/{id}"`.

Программа считает захват успешным при ответе 2xx. Ответы 404, 409, 410 и 422 означают «тикет уже занят»: такой тикет пропускается без уведомления.

### 6.5. Капча, двухфакторный вход (2FA) или вход через корпоративный SSO

В этих случаях программа не сможет входить сама. Выберите в мастере способ входа **«2 — готовый токен/cookie из браузера»**. Подробная пошаговая инструкция для входа через Telegram — в разделе [6.6](#66-сайт-со-входом-через-telegram-войти-через-telegram), для капчи, 2FA и SSO она та же:
В этих случаях программа не сможет входить сама. Выберите в мастере способ входа **«2 — готовый токен/cookie»**:
1. Войдите на сайт в браузере как обычно.
2. В DevTools → Network щёлкните по любому запросу к API (например, по запросу списка) → Headers → **Request Headers**.
3. Если там есть `Authorization: Bearer eyJ...`, скопируйте значение **без слова `Bearer`**. Имя заголовка — `Authorization`, схема — `Bearer`.
4. Если `Authorization` нет, скопируйте значение заголовка `Cookie` целиком. Имя заголовка — `Cookie`, схема пустая.

Такой токен рано или поздно истечёт (через часы или дни, зависит от сайта). Тогда бот пришлёт предупреждение `⚠️ autoticket: вход истёк или отклонён сервером…`. Повторите шаги 1–4 и выполните `autoticket setup`: Enter оставит прежние ответы, менять нужно только токен. Работающая программа сама перечитает `config.toml` и в логе появится строка `config.toml изменился: применяю новые настройки входа`.

### 6.6. Сайт со входом через Telegram («Войти через Telegram»)

На многих сайтах нет пароля: нажимаешь «Войти через Telegram», подтверждаешь вход в приложении Telegram, и дальше сайт тебя «помнит». Это работает так:

- Сам вход через Telegram программа пройти **не может и не должна**: Telegram каждый раз просит подтвердить вход в приложении. Это сделано, чтобы никакой скрипт не мог войти за вас.
- Но после входа сайт выдаёт **свою обычную сессию**: cookie (чаще всего) или токен `Authorization: Bearer …`. Именно её отправляет браузер с каждым запросом, и именно её можно отдать программе. Telegram для этого больше не нужен.

Если сессия на сайте «не пропадает», хватит одного раза.

**Шаги:**

1. Откройте сайт техподдержки в **отдельном профиле браузера** (Chrome/Edge: значок профиля справа вверху → «Добавить»). Подойдёт и окно инкогнито (Ctrl+Shift+N), но отдельный профиль надёжнее. Зачем отдельный: у программы будет своя сессия. Если вы выйдете из сайта в основном браузере, программа продолжит работать.
2. Войдите через Telegram как обычно.
3. Откройте страницу со списком тикетов, нажмите F12 → **Network** → **Fetch/XHR** и обновите страницу (F5).
4. Щёлкните запрос списка тикетов (раздел 6.3) → **Headers** → **Request Headers**:
   - есть строка `Authorization: Bearer eyJ…` → скопируйте значение **без слова `Bearer`**;
   - нет `Authorization` → найдите строку `Cookie:` и скопируйте **всё её значение целиком** (вида `sid=…; csrftoken=…; lang=ru`). Не выбирайте отдельные cookie, программе нужна вся строка. Если случайно скопируете вместе со словом `Cookie:`, ничего страшного: программа его отрежет.
   - Cookie с пометкой HttpOnly видны в этом заголовке тоже (а ещё на вкладке Application → Cookies), но проще взять заголовок.
   - Важно: если API сайта живёт на другом адресе, чем страница (например, страница `www.site.ru`, а запросы идут на `api.site.ru`), то `base_url` в настройках должен быть адресом **API**, и Cookie нужно копировать из запроса к API.
5. Выполните `autoticket setup` и ответьте:
   - `Способ входа …` → `2`;
   - `Токен или cookie из DevTools (без слова Bearer)` → вставьте скопированное (символы не отображаются);
   - `Имя заголовка (Authorization или Cookie)` → `Cookie` (или Enter, если у вас `Authorization`);
   - `Схема перед токеном («-» — без схемы)` → для Cookie Enter или `-` (схемы у cookie нет), для Authorization — `Bearer`.
6. Закройте вкладку или окно, **не нажимая «Выйти»** на сайте. «Выйти» обычно удаляет сессию на сервере, и программа тоже окажется «выкинута».
7. Проверьте: `autoticket run`. В логе не должно быть `вход истёк или отклонён сервером`. Онлайн-проверка в конце `autoticket setup` тоже покажет, сколько тикетов программа видит в списке.

**Почему сессия будет жить долго:**

- Программа обращается к сайту раз в секунду (интервал опроса). У многих сайтов срок сессии «скользящий», то есть он продлевается при каждом обращении, так что сессия не протухает от бездействия.
- Если сайт сам меняет cookie (присылает новый через `Set-Cookie`, так «вечные» сессии обычно и устроены), программа принимает новое значение, как браузер, и сохраняет его в файл `session.json` рядом с `config.toml` (права только для вашего пользователя). После перезагрузки она продолжит со свежей сессией, а не со старой из настроек. В логе это выглядит так (значения cookie в лог не пишутся никогда):

  ```
  INFO autoticket::helpdesk: cookie сессии взяты из /tmp/at-tg/session.json
  INFO autoticket::helpdesk: сервер обновил cookie сессии, сохранено в session.json
  ```

  Путь к `session.json` показывает `autoticket paths`. Когда вы через `autoticket setup` вставляете **новый** cookie, программа замечает это и берёт новый, а не сохранённый.

**Если сайт держит короткий Bearer-токен и браузер «тихо» его обновляет.** Так устроены некоторые сайты-приложения: токен живёт 5–15 минут, а потом страница сама делает запрос вроде `POST /api/auth/refresh` и получает новый. Найдите этот запрос в Network (оставьте вкладку открытой на 15–20 минут с включённым Preserve log и посмотрите, что появилось). Если он есть, впишите в `config.toml` в секцию `[helpdesk]` (или ответьте на вопросы мастера в ветке «Настроить пути API сейчас? → y»):

```toml
refresh_path = "/api/auth/refresh"       # путь запроса обновления
refresh_method = "POST"                  # его метод
refresh_token_pointer = "/access_token"  # где в ответе новый токен; "" — сайт обновляет только cookie
# refresh_body = '{}'                    # тело запроса, если оно есть
```

Тогда при ответе 401/403 программа один раз вызовет обновление и повторит запрос. Если обновление не удалось, будет обычное предупреждение в Telegram. Если поле `refresh_path` пустое (так по умолчанию), обновления нет.

**Подводные камни:**

| Что происходит | Что делать |
|---|---|
| Сайт разрешает только одну сессию: вход с телефона или другого браузера «выкидывает» программу | Придёт ⚠️ в Telegram. Повторите шаги 1–5. Работайте с сайтом в том же отдельном профиле, где брали cookie, или договоритесь, что программа — отдельная сессия |
| Сессия привязана к браузеру (User-Agent) и сразу даёт 401 | Скопируйте из того же запроса заголовок `User-Agent` и добавьте его в `config.toml` (см. 6.7): `[helpdesk.extra_headers]` и строку `"User-Agent" = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) …"` |
| Сессия привязана к IP-адресу | Запускайте программу на том же компьютере или в той же сети, где входили через Telegram. Для сервера войдите через браузер на самом сервере или через тот же VPN |
| Нажали «Выйти» в этом профиле, или сайт завершил все сессии | Сессия больше не работает: повторите шаги 1–5 |
| Сайт требует CSRF-заголовок (`X-CSRF-Token`, `X-XSRF-TOKEN`) для «Взять» | Скопируйте его из запроса «Взять» в `[helpdesk.extra_headers]` (6.7) |

### 6.7. Особые заголовки
### 6.6. Особые заголовки

Некоторые сайты отвечают на запросы API только при определённом заголовке, например `X-Requested-With: XMLHttpRequest` или `X-CSRF-Token`. Если без него не работает, а в браузере он есть, добавьте его в конец секции `[helpdesk]` в `config.toml`:

```toml
[helpdesk.extra_headers]
"X-Requested-With" = "XMLHttpRequest"
```

## 7. Первый запуск: autoticket setup

Запустите мастер настройки **в обычном окне терминала** (не через автозапуск):

```bash
autoticket setup
```

Мастер задаёт вопросы по порядку. В квадратных скобках показано значение по умолчанию: **Enter** его принимает. Если ответ **`-`** (минус), поле остаётся пустым.

1. **`Адрес сайта техподдержки`**: например `https://support.example.com`, обязательно с `https://`.
2. **`Способ входа: 1 — логин и пароль, 2 — готовый токен/cookie из браузера (вход через Telegram, SSO, капча) [1]`**: `1` или `2` (см. раздел 6.5).
2. **`Способ входа: 1 — логин и пароль, 2 — готовый токен/cookie из браузера [1]`**: `1` или `2` (см. раздел 6.5).
3. Для способа 1:
   - **`Логин`**;
   - **`Пароль (ввод не отображается)`**: при вводе пароля на экране ничего не появляется, даже звёздочек. Это нормально, напечатайте пароль и нажмите Enter.

   Для способа 2:
   - **`Токен или cookie из DevTools (без слова Bearer)`**: тоже без отображения;
   - **`Имя заголовка (Authorization или Cookie) [Authorization]`**;
   - **`Схема перед токеном («-» — без схемы) [Bearer]`**: для `Cookie` ответьте `-`.
4. **`Настроить пути API сейчас? (иначе — значения по умолчанию, их можно поправить в config.toml) [y/N]`**:
   - `y`: мастер спросит по очереди всё, что вы выписали в разделе 6: путь входа, поля логина и пароля, JSON Pointer токена (только для способа 1), путь списка, JSON Pointer массива, id и темы, HTTP-метод захвата, путь захвата (обязательно с `{id}`), JSON-тело захвата, ссылку на тикет; для способа 2 ещё путь обновления сессии (refresh) и, если он задан, JSON Pointer нового токена (раздел 6.6);
   - `y`: мастер спросит по очереди всё, что вы выписали в разделе 6: путь входа, поля логина и пароля, JSON Pointer токена (только для способа 1), путь списка, JSON Pointer массива, id и темы, HTTP-метод захвата, путь захвата (обязательно с `{id}`), JSON-тело захвата, ссылку на тикет;
   - Enter (или `n`): останутся значения по умолчанию (`/api/tickets?status=new` и `/api/tickets/{id}/assign`). Их можно поправить потом в `config.toml` (раздел 8). Фильтр `filter_*`, `extra_fields`, `list_method`/`list_body` и `extra_headers` мастер не спрашивает: их задают только в файле.
5. **`Токен бота от @BotFather`**: вставьте токен из шага 5 (не отображается). Вставка в PowerShell — правой кнопкой мыши или Ctrl+V, в терминале Linux — Ctrl+Shift+V.
6. **`chat_id (число; Enter — определить автоматически)`**: просто нажмите **Enter**.
7. **`Интервал опроса, мс (не меньше 250) [1000]`**: как часто проверять список. Оставьте 1000, если нет причин менять (см. [нагрузка на сервер](#программа-слишком-часто-опрашивает-сервер--как-снизить-нагрузку)).

Затем начинается **онлайн-проверка** (её можно пропустить флагом `--no-verify`):

```

```

- Когда мастер напишет «отправьте ему /start», откройте бота в Telegram и отправьте `/start` ещё раз, даже если уже нажимали Start в шаге 5. Мастер ждёт до 3 минут. Если сообщение так и не придёт, он попросит ввести chat_id вручную (его покажет бот **@userinfobot**).

```
сессия: /tmp/at-guide/session.json
логи:   /tmp/at-guide/logs
замеры: /tmp/at-guide/claims.csv
```

- Файл с паролем и токенами **не лежит в папке проекта** и не попадёт в GitHub. В `.gitignore` также указан `config.toml` на случай, если вы положите его рядом.

|---|---|---|
| `poll_interval_ms` | `1000` | интервал опроса списка, мс; меньше 250 программа не поставит |
| `max_backoff_ms` | `60000` | максимальная пауза между попытками при ошибках; пауза после отклонённого входа |
| `request_timeout_ms` | `5000` | таймаут одного запроса, мс (от 500 до 120000) |

## 9. Запуск и проверка, что всё работает

Сначала запустите программу вручную, чтобы увидеть, что она делает:

```bash
autoticket run
```

(`autoticket` без команды делает то же самое.) Остановить — **Ctrl+C**.

Если настроек ещё нет, `run` в окне терминала сам запустит мастер из раздела 7. После этого программа больше ничего не спрашивает.

### Что вы должны увидеть

Сразу после старта:

```
… INFO autoticket::worker: autoticket запущен: https://support.example.com опрашивается каждые 1000 мс, замеры пишутся в …/claims.csv
… INFO autoticket::helpdesk: вход выполнен (токен получен)
```

После этого программа молчит, пока нет новых тикетов: это нормально, каждый опрос она в лог не пишет. Когда появится новый тикет:

```
… INFO autoticket::worker: тикет взят за 38.4 мс ticket=42 title=Не работает принтер
```

и в Telegram придёт сообщение такого вида:

```
✅ Взят тикет #42
Не работает принтер
priority: high
created_at: 2026-11-26T09:15:00Z
https://support.example.com/tickets/42
Время захвата: 38.4 мс (от обнаружения: 39.1 мс)
```

Если тикет успел взять кто-то другой, в логе будет `тикет уже занят (HTTP 409)`, а уведомления не будет.

Проверить только Telegram, не дожидаясь тикета:

```bash
autoticket test-notify
```

В ответ должно напечататься `Сообщение отправлено в чат 123456789.`, а в Telegram прийти «🔔 autoticket: тестовое уведомление…».

Чтобы проверить захват целиком, попросите коллегу создать тестовый тикет или создайте его сами.

### Как выглядит лог при проблемах (программа при этом не падает)

Вот настоящий запуск в проверочной среде с выдуманным сайтом `support.example.com`. Сайт недоступен, поэтому программа пишет ошибку и повторяет попытку с растущей паузой. Прогон остановлен через 5 секунд командой `timeout`:

```
2026-11-26T14:13:04.189330Z  INFO autoticket::worker: autoticket запущен: https://support.example.com опрашивается каждые 1000 мс, замеры пишутся в /tmp/at-guide/claims.csv
2026-11-26T14:13:04.209710Z  WARN autoticket::worker: сетевая ошибка: нет соединения: error sending request for url (https://support.example.com/api/auth/login); повтор через 2s
2026-11-26T14:13:06.225929Z  WARN autoticket::worker: сетевая ошибка: нет соединения: error sending request for url (https://support.example.com/api/auth/login); повтор через 4s
2026-11-26T14:13:09.114958Z  INFO autoticket::worker: получен сигнал остановки, завершаю работу
```

Пауза между попытками удваивается (2 с, 4 с, 8 с…) до `max_backoff_ms` (60 с) и сбрасывается, как только связь вернётся: в логе появится `связь с техподдержкой восстановлена`. Если связи нет больше 5 минут, бот пришлёт `⚠️ autoticket: техподдержка недоступна уже N мин: …`.

## 10. Автозапуск при старте системы

Перед этим шагом:
1. `autoticket setup` выполнен, и `autoticket run` работает вручную (раздел 9).
2. Программа установлена в постоянное место через `cargo install --path .` (раздел 4).
3. Ручной запуск остановлен (Ctrl+C), чтобы не было двух копий.

Включить автозапуск:

```bash
autoticket install-autostart
```

Выключить: `autoticket uninstall-autostart`.

### Windows

Команда создаёт в **Планировщике заданий** задание `autoticket`: программа запускается **при входе вашего пользователя в Windows** без окна (`run --background`), без ограничения по времени работы, с перезапуском раз в минуту при сбое. Задание сразу же запускается. Ожидаемый вывод:

```
Автозапуск включён: задание «autoticket» в Планировщике заданий (при входе в систему).
```

Проверка:
- `schtasks /Query /TN autoticket /V /FO LIST`: строка `Состояние: Выполняется` (Status: Running);
- или **Пуск → «Планировщик заданий» → Библиотека планировщика → autoticket**, вкладка «Журнал»;
- в Диспетчере задач на вкладке «Подробности» есть процесс `autoticket.exe`;
- свежий лог в `%APPDATA%\autoticket\data\logs\`.

**Работа после перезагрузки без входа в систему** (для компьютера, который стоит включённым, например в офисе). По умолчанию задание стартует, когда вы входите в Windows. Чтобы программа работала сразу после включения:
1. Откройте Планировщик заданий → задание `autoticket` → **Свойства**.
2. Вкладка «Общие»: выберите **«Выполнять для всех пользователей»** (Run whether user is logged on or not), Windows запросит ваш пароль.
3. Вкладка «Триггеры» → «Создать…» → «Начать задачу»: **«При запуске»** (At startup). Сохраните.

Настройки и логи при этом берутся из вашего профиля, как и при обычном запуске.

### Linux (сервер)

Команда создаёт пользовательскую службу systemd `~/.config/systemd/user/autoticket.service` и выполняет:

```bash
systemctl --user daemon-reload
systemctl --user enable --now autoticket.service
loginctl enable-linger $USER
```

`enable-linger` нужен для того, чтобы служба запускалась **после перезагрузки сервера без вашего входа** по SSH. Ожидаемый вывод:

```
Создан /home/ivan/.config/systemd/user/autoticket.service
Автозапуск включён. Проверка: systemctl --user status autoticket; логи: journalctl --user -u autoticket -f
```

Содержимое службы (на примере пути из `cargo install`):

```ini
[Unit]
Description=autoticket: автоматический захват тикетов техподдержки
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0

[Service]
Type=simple
ExecStart=/home/ivan/.cargo/bin/autoticket run
Restart=always
RestartSec=10
RestartPreventExitStatus=78
Environment=RUST_LOG=info

[Install]
WantedBy=default.target
```

`Restart=always` перезапускает программу через 10 секунд после любого завершения. Исключение — код 78 («нет или ошибка конфигурации»): перезапуск ничего бы не исправил, поэтому служба просто останавливается с понятной ошибкой в логе.

Проверка и управление:

```bash
systemctl --user status autoticket        # должно быть: active (running)
journalctl --user -u autoticket -f        # лог в реальном времени (Ctrl+C — выйти)
systemctl --user restart autoticket       # после autoticket setup или правки config.toml
systemctl --user stop autoticket          # остановить до следующей перезагрузки
loginctl show-user $USER -p Linger        # должно быть: Linger=yes
```

> В Docker-контейнерах, WSL без systemd и некоторых дешёвых VPS (OpenVZ) пользовательского systemd нет. Тогда `install-autostart` создаст файл службы, но не сможет её включить, и напечатает команды для ручного запуска (см. [Проблемы](#install-autostart-пишет-не-всё-получилось-сделать-автоматически)).

### macOS

Создаётся `~/Library/LaunchAgents/com.autoticket.plist` (запуск при входе, перезапуск при сбое) и загружается через `launchctl load -w`. Проверка: `launchctl list | grep com.autoticket`. Вывод программы пишется в `~/Library/Logs/autoticket.log`.

### Проверка после перезагрузки (обязательно сделайте один раз)

1. Перезагрузите компьютер или сервер (`sudo reboot`).
2. **Windows:** войдите в систему, подождите минуту. **Linux:** ничего не делайте, можно даже не заходить по SSH; для проверки зайдите через пару минут.
3. Убедитесь, что программа работает: Windows — `schtasks /Query /TN autoticket /V /FO LIST` и процесс `autoticket.exe`; Linux — `systemctl --user status autoticket`.
4. В свежем логе должна быть строка `autoticket запущен: …` со временем после перезагрузки.
5. Для полной уверенности: `autoticket test-notify`.

### После изменения настроек

`autoticket setup` и правка `config.toml` **не перезапускают** уже работающую программу. После них:
- Linux: `systemctl --user restart autoticket`
- Windows: `schtasks /End /TN autoticket`, затем `schtasks /Run /TN autoticket`
- macOS: `launchctl unload ~/Library/LaunchAgents/com.autoticket.plist && launchctl load -w ~/Library/LaunchAgents/com.autoticket.plist`

Исключение: новый пароль или токен для сайта программа подхватит сама, как только сервер отклонит старый вход.

## 11. Логи, замеры и команда bench

- **Логи:** `<папка данных>/logs/autoticket.ГГГГ-ММ-ДД.log`. Новый файл заводится каждый день, хранятся последние 14. Путь показывает `autoticket paths`. Посмотреть последние строки:
  - Windows: `Get-Content "$env:APPDATA\autoticket\data\logs\autoticket.*.log" -Tail 50`
  - Linux: `tail -n 50 ~/.local/share/autoticket/logs/autoticket.*.log` или `journalctl --user -u autoticket -n 50`
- **Подробный лог** для поиска проблемы: запустите вручную с переменной `RUST_LOG=debug`:
  - Windows: `$env:RUST_LOG="debug"; autoticket run`
  - Linux: `RUST_LOG=debug autoticket run`
- **claims.csv**: одна строка на каждую попытку захвата, с колонками `timestamp_utc,ticket_id,claim_rtt_ms,detect_to_claim_ms,outcome`. `claim_rtt_ms` — сколько миллисекунд занял запрос «Взять». Файл открывается в Excel.
- **Замер скорости до вашего сервера:** команда `autoticket bench` отправляет 20 запросов списка по уже открытому соединению и **ничего не берёт**. Строка «тёплое соединение» показывает минимально возможное время захвата с вашей машины:

  ```bash
  autoticket bench                                 # ваш сайт техподдержки (нужен config.toml)
  autoticket bench --n 50 --interval-ms 500        # больше замеров, реже
  autoticket bench --url https://api.telegram.org  # любой адрес, без входа
  ```

  Что означают цифры и почему 10 мс достижимы только рядом с сервером, объяснено в [docs/REPORT.md](REPORT.md).

## 13. Проблемы и их решения

### `cargo` / `rustc` не является внутренней или внешней командой (command not found)

Терминал открыт до установки Rust. Закройте и откройте его заново. На Linux можно выполнить `source ~/.cargo/env`. Если не помогло, проверьте, что папка `%USERPROFILE%\.cargo\bin` (`~/.cargo/bin`) есть в PATH.

### `error: linker 'link.exe' not found` (Windows) или `linker 'cc' not found` (Linux)

Не установлен компилятор C. Windows: поставьте Visual Studio Build Tools с нагрузкой «Разработка классических приложений на C++» (раздел 2) и откройте новый терминал. Linux: `sudo apt install -y build-essential`.

### `failed to run custom build command for 'ring'`

Та же причина: нет компилятора C (см. предыдущий пункт). На macOS выполните `xcode-select --install`.

### `feature 'edition2024' is required` или ошибки про `let` chains

Слишком старый Rust. Выполните `rustup update stable`, нужна версия 1.88 или новее.

### Сборка падает: `Killed`, `signal: 9`, «не хватает памяти»

На сервере мало оперативной памяти. Добавьте файл подкачки и собирайте в один поток:

```bash
free -h                                   # если Swap уже есть (≥ 2 ГБ), пропустите 4 строки ниже
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
cargo build --release -j1
```

Если `fallocate` пишет `Text file busy`, файл подкачки `/swapfile` уже есть и работает: просто запустите `cargo build --release -j1`. Другой путь — собрать программу на своём компьютере с тем же типом ОС и скопировать на сервер один файл `target/release/autoticket`.

### ``ERROR autoticket: нет конфигурации: запустите `autoticket setup` в терминале…``

Программа запущена без настроек и без терминала (автозапуск), поэтому вопросы задать некому. Она завершается с кодом 78, systemd её не перезапускает. Настоящий вывод:

```
2026-11-26T14:13:12.125498Z ERROR autoticket: нет конфигурации: запустите `autoticket setup` в терминале, чтобы ввести данные для входа (ожидался файл /tmp/at-empty/config.toml)
```

Выполните `autoticket setup` в обычном окне и перезапустите службу. Если вы задавали `--config-dir`/`AUTOTICKET_CONFIG_DIR`, служба должна видеть ту же папку: выполните `install-autostart` ещё раз из того же окружения.

### ``ошибка в …config.toml; исправьте файл или запустите `autoticket setup` ``

В файле синтаксическая ошибка TOML или недопустимое значение: в сообщении будет указано какое, например `helpdesk.claim_path должен содержать {id}`. Частые причины: строка без кавычек, путь Windows с одиночными `\` (пишите в одинарных кавычках `'C:\путь'`), удалённая скобка секции `[helpdesk]`.

### `сетевая ошибка: …` и `повтор через …`

Нет связи с сайтом: неверный `base_url`, нет интернета, VPN не подключён, сайт доступен только из офисной сети. Проверьте адрес в браузере на той же машине. Программа будет повторять попытки сама. Проверьте задержку командой `autoticket bench`.

### `вход истёк или отклонён сервером (HTTP 401)` / `HTTP 403`

- Способ «логин и пароль»: неверный логин или пароль, сменился пароль, заблокирован аккаунт. Выполните `autoticket setup`.
- Способ «токен» (в том числе вход через Telegram): сессия истекла, сайт «выкинул» её после входа с другого устройства, или вы нажали «Выйти». Скопируйте новый cookie или токен по шагам раздела [6.6](#66-сайт-со-входом-через-telegram-войти-через-telegram) и выполните `autoticket setup`. Если сразу после вставки снова 401, посмотрите там же таблицу «Подводные камни» (привязка к User-Agent или IP).
- Способ «токен»: токен истёк, скопируйте новый (раздел 6.5) и выполните `autoticket setup`.
- После отклонённого входа программа ждёт `max_backoff_ms` (60 с) до следующей попытки, чтобы аккаунт не заблокировали за перебор, и присылает предупреждение в Telegram (не чаще раза в 30 минут).

### `не удалось войти: в ответе входа нет токена по пути /token`

Токен в ответе входа лежит в другом поле. Посмотрите Response запроса входа (раздел 6.2) и укажите правильный `token_pointer`. Если токена в ответе нет совсем (сайт ставит cookie), укажите `token_pointer = ""`.

### `сервер ответил HTTP 404: …` при опросе списка, или `не удалось разобрать ответ: …`

Неверный `list_path` или ответ устроен иначе, чем указано в `list_items_pointer`/`id_pointer`. Сверьте с запросом из DevTools (раздел 6.3). Если сервер вернул HTML вместо JSON, скорее всего, вы указали адрес страницы, а не API.

### `не удалось взять тикет: HTTP 400/405/500 … (попытка 1/3)`

Запрос «Взять» не принят: неверный `claim_method`, `claim_path` или тело `claim_body`. Сверьте с DevTools (раздел 6.4). После 3 неудачных попыток программа перестаёт брать этот тикет (`Попыток: 3, больше не пытаюсь`), чтобы не нагружать сервер.

### На сайте есть новые тикеты, но программа их не берёт, а лог молчит

Скорее всего, программа видит пустой список: неверный `list_items_pointer` или слишком строгий `filter_pointer`/`filter_values`. Запустите `RUST_LOG=debug autoticket run` или повторите проверку `autoticket setup` (она покажет, сколько тикетов найдено).

### `сервер вернул 429 Too Many Requests, пауза …`

Сервер просит реже обращаться к нему. Программа сама выдержит паузу из заголовка `Retry-After`. Если это повторяется, увеличьте `poll_interval_ms` (например, до 2000).

### `Telegram отклонил сообщение: … Проверьте токен бота и chat_id (autoticket setup)`

Неверный токен бота (`401 Unauthorized`), неверный chat_id (`400 chat not found`) или вы не нажали Start у бота / заблокировали его (`403 Forbidden`). Откройте бота, нажмите Start и выполните `autoticket setup`.

### `autoticket test-notify` пишет `Ошибка: ошибка Telegram: HTTP 401: Unauthorized`

Неверный токен бота: скопирован не целиком или отозван через `/revoke`. Скопируйте токен из @BotFather заново (`/mybots` → бот → API Token) и выполните `autoticket setup`. Если ошибка `HTTP 400: Bad Request: chat not found`, неверен chat_id: отправьте боту `/start` и повторите `setup`, нажав Enter на вопросе о chat_id.

### `Telegram: …; повтор через …` / `Telegram недоступен (…): сообщение не доставлено после 10 попыток`

Нет связи с `api.telegram.org`. В некоторых сетях Telegram заблокирован, тогда нужен VPN или сервер в другой стране. Тикеты при этом всё равно берутся, а сообщения ждут в очереди с повторами (до 10 попыток на сообщение).

### `install-autostart` пишет «Не всё получилось сделать автоматически»

Программа напечатает, какая команда не сработала и что выполнить вручную. Например, в контейнере без systemd:

```
Создан /home/user/.config/systemd/user/autoticket.service
Не всё получилось сделать автоматически:
  - `systemctl --user daemon-reload` завершилась с ошибкой: Failed to connect to bus: No medium found
  - `systemctl --user enable --now autoticket.service` завершилась с ошибкой: Failed to connect to bus: No medium found
  - `loginctl enable-linger user` завершилась с ошибкой: Failed to connect to bus: No such file or directory
Выполните вручную:
  systemctl --user daemon-reload
  systemctl --user enable --now autoticket.service
  loginctl enable-linger user
Ошибка: автозапуск настроен не полностью
```

- `Failed to connect to bus` / `systemctl: command not found`: на этой машине нет пользовательского systemd (Docker, WSL, OpenVZ). Варианты: включить systemd в WSL (`/etc/wsl.conf` → `[boot]` `systemd=true`, затем `wsl --shutdown`), или запускать программу через `cron`: `crontab -e` → строка `@reboot /home/ivan/.cargo/bin/autoticket run --background`, или поставить её системной службой (root) по образцу файла `~/.config/systemd/user/autoticket.service`.
- `loginctl enable-linger … Access denied`: выполните `sudo loginctl enable-linger $USER`.
- Windows, `schtasks … Отказано в доступе`: запустите PowerShell от своего обычного пользователя (не «от имени администратора» другого аккаунта) или создайте задание вручную командой, которую напечатала программа.

### Служба запущена, но сразу останавливается (Linux: `status=78`)

В логе (`journalctl --user -u autoticket -n 50`) будет причина: нет `config.toml` или в нём ошибка. Исправьте и выполните `systemctl --user restart autoticket`.

### Две копии программы

Если программа работает и вручную, и через автозапуск, обе будут опрашивать сервер, и один тикет может прийти в Telegram дважды. Остановите ручной запуск (Ctrl+C) или службу.

### Программа слишком часто опрашивает сервер / как снизить нагрузку

По умолчанию — один лёгкий запрос списка в секунду. Минимум, который можно поставить, — 250 мс. Ставить меньше 500 мс обычно бессмысленно: тикет будет обнаружен на доли секунды раньше, а нагрузка на сервер вырастет в разы. При ошибках интервал сам увеличивается до `max_backoff_ms`.

## 15. Шпаргалка

| Команда | Что делает |
|---|---|
| `autoticket setup` | ввести или изменить данные (с онлайн-проверкой); `--no-verify` — без проверки |
| `autoticket run` | работать в текущем окне (Ctrl+C — стоп); `--background` — без вывода в консоль |
| `autoticket test-notify` | тестовое сообщение в Telegram |
| `autoticket bench` | замер задержки до сайта (тикеты не берутся); `--n`, `--interval-ms`, `--url` |
| `autoticket install-autostart` | включить автозапуск |
| `autoticket uninstall-autostart` | выключить автозапуск |
| `autoticket paths` | где лежат config.toml, логи, claims.csv |
| `autoticket --config-dir ПАПКА …` | использовать другую папку настроек (для любой команды) |
| `autoticket --help`, `autoticket --version` | справка и версия |
